## Deployment

* `Dockerfile`: a multi-stage build; the final image has only the JRE and the
  jar, and runs as an unprivileged user.
* `frontend/vercel.json`: the website on Vercel, with page routes and
  security headers.
* `render.yaml`: one-click Render blueprint (web service, PostgreSQL and a
  Key Value instance for Redis, both closed to the internet), with secrets
  entered in the dashboard and the app role's password generated by Render.
* `docker-compose.yml` plus `.env.example`: the full stack on any machine:
  PostgreSQL and Redis with health checks, the app as its restricted role.
  CI starts it on every push and runs the first-admin script against it.
* `GET /api/health` for the platform's health checks: database and Redis,
  `UP` or `DOWN` each.

**To do yourself:** create the Vercel and Render accounts, follow the three
step guides in important/ (STEP_1 to STEP_3), set the secrets, and put the
live Vercel URL at the top of the README.
